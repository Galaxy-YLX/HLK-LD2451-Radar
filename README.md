# HLK-LD2451-Radar

基于 HLK-LD2451 的便携雷达。上位机沿用 `EaiLidar-Viewer` 的同一套方案：纯 C++ 协议层 + Qt6 显示层，绿黑雷达主题。

## 方案设计

| 层 | 位置 | 说明 |
| --- | --- | --- |
| 数据模型 | `src/core/` | `Target`（角度/距离/速度/信噪比 + 直角坐标）、`Scan`（一帧目标） |
| 协议解析 | `src/protocol/` | `parser`（数据帧、ACK 解析 + 命令帧构造）、`frame_assembler`（双帧头字节流组帧）。纯 C++ 无 Qt 依赖 |
| 传输层 | `src/transport/` | `SerialTransport`：Qt SerialPort `readyRead` → 组帧 → 解析 → `scanReady` / `ackReady` 信号 |
| 显示层 | `src/ui/` | `RadarView`：**±15° 扇形视图**，雷达位于底部中心（距离弧、角度刻度、目标着色、速度矢量、余辉轨迹） |
| 应用层 | `src/app/` | `MainWindow`（串口连接、模块命令、目标表格、HUD）、`main`（雷达主题） |
| 测试 | `tests/` | 以协议文档 §7 实例帧为基准的纯 C++ 单测 |

## 协议要点

- **串口**：115200 / 8N1，小端。
- **上报数据帧**：`F4 F3 F2 F1` + 长度(2B) + 帧内数据 + `F8 F7 F6 F5`。帧内数据 = 目标数(1B) + 报警(1B) + N×5B（角度、距离、速度方向、速度值、信噪比）；无目标时长度字段为 0。
- **角度** = 上报值 − `0x80`（°），**距离**单位为米，**速度**单位 km/h。
- **探测角度**（手册 V1.03 性能参数）：水平 **±15°**、垂直 ±7°。协议里的 −128~+127° 只是角度字段编码范围，并非真实波束；视图按 ±15° 绘制扇形，超出该角度的上报目标不在视图中显示（目标表格仍列出全部）。
- **命令 / ACK 帧**：`FD FC FB FA` + 长度(2B) + 帧内数据 + `04 03 02 01`；ACK 命令字 = 原命令字 `| 0x0100`，状态 `0x0000` 成功。
- **配置流程**：使能配置 `0x00FF` → 查询/配置命令 → 结束配置 `0x00FE`（界面中的读取版本/读取参数/重启已封装整条流程）。

## 构建与运行

```bash
cmake -S . -B build -G Ninja
cmake --build build -j4
ctest --test-dir build --output-on-failure   # 协议单测
./build/ld2451_viewer                        # 连接串口后显示实时目标
./build/ld2451_viewer --demo                 # 无硬件时用模拟目标演示显示效果
```

Fedora 上打开 `/dev/ttyUSB0` 需先加入 `dialout` 组：`sudo usermod -aG dialout $USER`，重新登录后生效。

界面说明：右侧「演示数据」按钮可随时切换演示；「按字段定义 / 按示例解析」用于切换速度方向字节的解释；量程、镜像、点大小、信噪比下限、余辉、速度矢量、数值标签均可在界面调整。

## 已知协议歧义（见 `参考文件/LD2451串口通信协议文档.md`）

1. **速度方向定义自相矛盾**：§6.2 字段说明为 `0x01` 靠近、`0x00` 远离；§7 示例解析却把 `0x00` 解释为靠近。解析器默认按 §6.2，界面可切换到「按示例解析」，接硬件后按实测确定。
2. **固件版本 ACK 长度字段笔误**：§5.7 示例长度字段为 `0x0B`，但帧内数据实为 12 字节。组帧器在帧尾校验失败时于 ±4 字节内重新定位帧尾，解析器按整帧长度推断帧内数据，因此两种写法都能正确解析。
3. §7 示例中目标 2 的距离字节原文误印为 `IE`，实为 `1E`（30 m），协议文档已勘误。
